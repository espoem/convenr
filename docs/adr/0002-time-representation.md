# ADR 0002: Time representation

Status: accepted, 2026-11-16.

## Context

An event's slots must mean the same thing to every participant, in any time zone, on both sides of a clock change. Two kinds of events exist: dated events and weekday events. They need different answers.

Two existing open-source tools show the two approaches for weekday events. Crab Fit stores weekday slots as UTC strings (`HHmm-d`) and converts them "based on the current date", so the same stored slot shows a different local time after a clock change. Timeful stores an IANA time zone with each weekday event and a "start on Monday" flag.

## Decision

1. **Every event has a reference zone**, stored as an IANA zone name. It is set at creation.
2. **A dated event's slot is a UTC instant.** Slots are generated by walking wall-clock times in the reference zone and converting each to UTC. They are displayed in the viewer's zone.
3. **A weekday event's slot is a pair: ISO day of week (1 to 7) and minutes after midnight.** It is a wall-clock time in the reference zone. It is never converted. Viewers in another zone see the same numbers and a notice.
4. **Clock changes in dated events.** A wall-clock time that does not exist on a date produces no slot. A wall-clock time that occurs twice produces one slot, at its first occurrence.
5. **The daily range stays within one day.** Start is at least 00:00 and end is at most 24:00. Ranges across midnight are not supported.
6. **The first day of week is a display setting of the event.** It orders the columns of a weekday event and the weeks of the date picker. It does not change which slots exist.
7. **Time arithmetic uses the `Temporal` API.** Node.js 26 provides it. Browsers that lack it get a polyfill. `Date` is not used for zone conversion.
8. **Zone data comes from the runtime.** The server and the browser may disagree for a zone whose rules changed recently. The server's result is authoritative, because the server generates the slots and the browser only displays them.

## Storage

- Dated slot: `timestamptz`, always written in UTC.
- Weekday slot: two small integers, day of week and minute of day.
- A response stores the slot keys the participant marked, one row per slot, with a foreign key to the participant.

## Consequences

- A weekday event answers "which evening each week", and the answer does not move when clocks change. Participants in other zones convert in their heads. This is stated on the page.
- A dated event on a clock-change day has one hour fewer or the same number of slots, never a duplicated hour.
- Allowing ranges across midnight later needs no change to stored data, only to slot generation and to the grid's row logic.
- Slot length, day mode and reference zone cannot change after the first response, because every stored slot key depends on them.
